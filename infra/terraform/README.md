# AWS infrastructure (ADR 0030)

Terraform for the platform on AWS: ECS Fargate, RDS PostgreSQL Multi-AZ, S3, KMS, SES, an
HTTPS load balancer with WAF, backups and alarms. Staging and production are separate AWS
accounts in us-east-1, with us-west-2 as the recovery region. A third account holds a locked
backup vault.

```
modules/platform       one environment (network, database, storage, keys, services, mail,
                       backups, alarms, account security); tests/ checks it with mocked AWS
modules/backup-vault   the locked vault in the backup account
modules/state-backend  a state bucket for one account
envs/staging           staging (its own account)
envs/production        production (its own account)
envs/backup            the backup account
```

## First time, per account

1. Create the state bucket with local state, then keep that state file safe (or import the
   bucket into the environment's state later):

   ```bash
   cd infra/terraform/modules/state-backend
   terraform init && terraform apply -var bucket_name=acct-<env>-terraform-state-<account id>
   ```

2. In `envs/<env>`, copy `backend.hcl.example` to `backend.hcl` and `terraform.tfvars.example`
   to `terraform.tfvars`, fill them in, then:

   ```bash
   terraform init -backend-config=backend.hcl
   terraform apply
   ```

   The first apply needs images in the environment's ECR repositories, which Terraform creates.
   Apply once with `-target=module.platform.aws_ecr_repository.app`, push the images (the deploy
   workflow, or `docker build`/`docker push`), then apply everything. The launch checklist
   (`docs/launch-checklist.md`) lists the rest: SES production access, provider secrets, the
   first field key, the GitHub environments.

3. Commit the provider lock file for the platforms you use:
   `terraform providers lock -platform=linux_amd64 -platform=darwin_arm64`.

## Secrets

Database passwords, `SIGNING_KEY` and `PASSWORD_PEPPER` are generated by Terraform with
ephemeral resources and written to RDS and Secrets Manager through write-only attributes: they
are never in the plan or the state. Bump `db_passwords_version` or `signing_key_version` to make
new ones (runbook: `docs/runbooks/rotate-secrets.md`). The pepper never changes.

Provider credentials (Stripe, Plaid, Intuit, Anthropic) are listed in `provider_secret_names`;
Terraform creates empty secrets and an operator puts the values in Secrets Manager.

## Checks

```bash
terraform fmt -check -recursive infra/terraform
cd infra/terraform/modules/platform && terraform init -backend=false && terraform test
cd infra/terraform/envs/production && terraform init -backend=false && terraform validate
```

CI runs these on every pull request (the `terraform` job in `.github/workflows/ci.yml`).
